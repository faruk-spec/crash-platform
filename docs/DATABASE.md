# Database Schema Architecture

The platform relies on a normalized MySQL 8.0 database partitioned across 7 functional domains.

## Table Inventory (25 Tables)
1. `users`: Administrative user credentials and access state.
2. `roles`: Role definitions (`SuperAdmin`, `Operator`, `Auditor`).
3. `permissions`: Granular action rights.
4. `user_roles`: User-role pivot mapping.
5. `devices`: Registered Android hardware identities.
6. `device_tokens`: Push notification tokens (FCM).
7. `device_heartbeats`: Hardware health telemetry (battery, RAM, network).
8. `device_configurations`: Remote activation control settings.
9. `configuration_versions`: Immutable audit snapshots of settings.
10. `application_releases`: Signed APK/AAB distribution catalog.
11. `game_rounds`: Ground-truth crash records and animation summaries.
12. `raw_observations`: Unfiltered WebSocket and inspect JSON payloads.
13. `visual_features`: Computer vision spline metrics and optical flow.
14. `analysis_results`: Output generated by the AI/ML statistical engine.
15. `prediction_records`: Signals broadcast to connected devices.
16. `prediction_evaluations`: Ground-truth verification and Brier scores.
17. `ml_datasets`: Versioned historical training datasets.
18. `ml_models`: Model registry storing candidate and active models.
19. `sync_batches`: Batch transaction metadata.
20. `sync_failures`: Dead-letter queue for rejected payloads.
21. `github_repositories`: Registered repos and webhook secrets.
22. `build_artifacts`: Android build outputs generated by GitHub Actions.
23. `deployments`: Release deployment history on the VPS.
24. `system_settings`: Global key-value operational configuration.
25. `audit_logs`: Security and administrative audit trail.
